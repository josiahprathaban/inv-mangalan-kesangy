# Mangalan & Kesangy

A simple wedding invitation built with HTML, CSS, JavaScript, and Anime.js. No framework, package installation, or build step.

Open `index.html` directly, or serve the directory with `python -m http.server 8000` and visit http://localhost:8000.

- `index.html` — invitation wording and layout
- `styles.css` — colors, typography, responsive layout, and print styles
- `script.js` — a names-only opening with a randomized character reveal, automatic invitation reveal, and scroll animations, respecting reduced motion
- `mangalan-kesangy.ics` — downloadable calendar event, 1 November 2026 at 10:00 AM Sri Lanka time
- `vendor/` — Anime.js 4.5.0 and its MIT license
- `assets/watercolor-paper.webp` — original watercolor paper texture, used in ivory and burgundy across the invitation

The opening uses preloaded local font files in `fonts/`, shown only after loading to avoid a visible typeface swap. The rest of the invitation uses Google Fonts, with local serif and sans-serif fallbacks. Anime.js is stored locally so the invitation and its animations do not depend on a CDN. The venue link opens a Google Maps search; a confirmed map pin can replace it later.

The design uses ivory paper and burgundy type. On a fresh visit, the bold ivory letters appear in a random order with a soft pop, clearing blur, and a fading glow on a burgundy background. After the fonts load, the background plants draw in completely before the randomized letter reveal starts. The finished names then hold for two seconds before the opening lifts away and the invitation slides upward beneath it in a synchronized 1.5-second theater-style transition. Character wrappers stay in place throughout the pause to prevent a change in spacing or text rendering; they are removed when the cover closes. Escape skips the opening. Every fresh load clears section fragments and resets scrolling to the top before showing the opening. Reduced-motion visitors go straight to the invitation at the top; without JavaScript, all content is available immediately.

The character reveal uses Anime.js `splitText`, `utils.shuffle`, and `stagger(75)` in `script.js`. The `setTimeout(finishOpening, 2000)` call controls the pause after the animation completes. Future artwork can be added without changing the content structure.

The watercolor background is preserved but currently disabled. To enable it again, change `data-watercolor="off"` to `data-watercolor="on"` on the first `<html>` element in `index.html`. It restores the texture on the opening, invitation, and closing. Generation details and the prompt are in `assets/README.md`.

The opening preserves two foreground flower sprigs at the top and bottom, currently hidden. To restore them, change `data-foreground-flowers="off"` to `data-foreground-flowers="on"` on the `<html>` element in `index.html`. The visible background is a sharp, faint dark-magenta meadow of individual flowers and leaves along the bottom edge (10% opacity on all screens, no blur). The top and bottom stem tips tuck slightly beyond the viewport edges. Both foreground and background artwork enter through stroke-following SVG reveal masks over 3.2–4 seconds per motif, with smooth sine easing and a slight stagger, then remain drawn. Each background stem sways independently with a randomized direction, angle, speed, and delay. The foreground keeps its gentle sway. The original filled pen strokes are rendered without an added outline, avoiding double contours. These loops run while the cover is visible and stop when the invitation opens or motion is reduced. The opening waits for the plant drawing to finish, then reveals the names and pauses before the vertical curtain transition. Extracted artwork is saved as `assets/opening-flower.svg` and `assets/opening-leaves.svg` and embedded in `index.html` so Anime.js can animate the paths, including when opened directly from disk. The supplied collection is unchanged.

Background plants are enlarged on desktop. Tablet screens show six spread-out stems, and mobile shows three larger stems at 0%, 50%, and 100%, preserving their aspect ratios and spacing. Hidden plants do not run sway animations.

The curtain transition uses an Anime.js timeline in `finishOpening`. It keeps scrolling and invitation links locked until both pages settle, then removes temporary transforms. Escape skips directly to the invitation; reduced-motion visitors bypass the opening and transition.

The upper opening background has two central hand-drawn hearts fixed at 15% opacity and eight neatly spaced smaller hearts with randomized sizes and 5-10% opacity. Anime.js draws the heart outlines and pulses each heart gently with independent timing; the flowers-finish-before-text sequence is preserved. All heart animations stop when the opening closes.

Background music uses `assets/bgm.mp3`, loops, and attempts autoplay immediately on load, before animation setup. It also retries when the media becomes playable and on page restoration. If the browser blocks audible autoplay, the first tap, touch, or key interaction starts it; JavaScript cannot override the browser's sound policy. The fixed sound button pauses/resumes playback, and a manual pause is respected. `music.js` is independent of the animation script, so reduced-motion visitors also get music controls.

Playback starts at 5% HTML media volume. On a gesture over HTTP(S), a Web Audio gain node applies a 0.05 gain with HTML media volume set to 1, keeping a 5% level on iPhone browsers that ignore HTML volume. Direct local-file previews use HTML media volume. Actual loudness also depends on the guest's device volume. No music begins until the browser permits playback.

The details below the names are four centered lines: date (larger), written ceremony time, venue (bold), and location (smaller). The thin SVG down arrow sits below with extra breathing room and links to the celebration section. Detail cards below are unchanged. Native scroll restoration is disabled; hash fragments are removed only on a fresh load, while section links still work during a visit. Scroll position is also reset before and after the opening transition.

`sparkles.js` adds a small pool of three single-color glints matching the ampersand, with 80% peak opacity to the inside names. Each twinkle chooses a random character edge, size, duration, rotation, and interval, without altering letter spacing or layout. The effect starts after the cover closes, pauses when the names are off screen or the tab is hidden, and respects reduced motion. The shine color is `.name-sparkles` in `styles.css`.

All devices use the same animation sequence and effects. Anime.js WAAPI runs the plant sway, heart pulse, character blur/pop/glow, and name sparkles through native browser animations. SVG drawing still uses Anime.js, targeting only motifs actually visible in the responsive layout. Finished flower masks are detached before the letters appear, so later sway no longer composites SVG masks. Embedded SVG coordinates are rounded to two decimal places, reducing the HTML from about 224 KB to 155 KB without changing the artwork at display sizes. The supplied SVG file is untouched. Art pauses in hidden tabs and is cancelled when the opening closes. Reduced-motion preferences remain respected.

Visit `/write` to create personalised invitation links. `write/index.html` provides the form, `write/write.css` styles it, and `write/write.js` generates the link and sharing message entirely in the browser. Static hosts serve this directory at `/write/`; no framework or backend is needed. Deploy the `write` directory alongside the invitation and keep directory index serving enabled. Relative assets and generated links also support deployment beneath a subdirectory.

Enter guest names, an optional personal note, and an editable sharing message. The default sharing message follows the guest names until manually edited; “Use default” restores it. The result includes a preview link, copy controls, WhatsApp, Telegram, email, and the device share sheet where supported. Nothing is sent until the sender chooses a sharing action and completes it in their app. Clipboard failures fall back to selecting the text for manual copying.

`personalize.js` displays `?guest=Kumar+and+Josiah` as “Dear Kumar and Josiah,” on the invitation. The optional `message` query parameter adds a personal note below the greeting. Both parameters are displayed as plain text, with length limits; the opening animation stays the same. Without those parameters the original invitation is shown. Names and personal notes are part of the generated URL, so anyone with that link can read them. Sharing-message edits remain in the composer and are not added to the invitation URL. Generate public sharing links from the deployed website; a localhost or file preview link is only useful on your own device.
